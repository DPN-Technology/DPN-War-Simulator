# Software Supply Chain

DPN Technology maintains a machine-readable dependency inventory for each published release.

## Release SBOMs

The `Supply Chain` GitHub Actions workflow scans the exact Git tag associated with the release, not the moving `main` branch.

Each release receives:

- `sbom.spdx.json` — SPDX JSON software bill of materials
- `sbom.cyclonedx.json` — CycloneDX JSON software bill of materials
- `SBOM_SHA256SUMS.txt` — SHA-256 hashes for both SBOM files
- `SBOM_MANIFEST.txt` — repository, release tag, source commit, scanner version, and generation time

SBOM generation uses Anchore Syft through the verified Anchore SBOM GitHub Action. The workflow is pinned to a specific action release and Syft release for repeatability.

## Dependency Graph

The SPDX generation step also submits a dependency snapshot to GitHub so dependency/security tooling has a repository-level inventory in addition to the release assets.

## Verification

After downloading the SBOM assets:

```bash
sha256sum -c SBOM_SHA256SUMS.txt
```

The release source ZIP has a separate `SHA256SUMS.txt` generated by the Release workflow.

## Release Integrity

The release process is designed so that:

1. CI validates the source.
2. A Git tag identifies the immutable release source.
3. The Release workflow packages that tagged source.
4. The Supply Chain workflow checks out the same tag.
5. SBOMs are generated from that tagged tree.
6. SBOM hashes and source-release hashes are published independently.

## Secret Handling

SBOM files are dependency and package inventories. They must not be used as a place to store credentials, keys, tokens, production databases, runtime configuration, or private operational data.

The normal repository secret/runtime-data guards remain in effect.

## Artifact Attestations

The repository is prepared for stronger provenance/attestation controls if the GitHub plan and repository policy support private-repository artifact attestations in the future.
