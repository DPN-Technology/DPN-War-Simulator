# Security Policy

## Supported Versions

The current `main` branch and current release line are the supported development targets.

## Reporting a Security Issue

Do not publish sensitive exploit details, credentials, tokens, private infrastructure information, or other confidential data in a normal GitHub issue.

Use GitHub private vulnerability reporting if enabled, or an established private DPN Technology security/administrative channel.

Include the affected version/component, reproduction steps, impact, and mitigation if known.

## Repository Safety

Never commit:
- Private keys or credentials
- API tokens
- Personal/private test data
- Proprietary third-party assets without permission
- Build outputs containing secrets
- Local environment files

## Historical and Reconstruction Integrity

Security reports are separate from historical-accuracy issues. Historical claims, reconstructed spaces, and gameplay abstractions should remain clearly labeled according to the project's historical-boundary documentation.
